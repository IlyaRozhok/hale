## Займы и вопрос о переводе
Слито в `main` и выкачено на сервер 3 ноября 2026 с согласия владельца, образ `hale-api:bb0f3e9f04fb` (предыдущий для отката: `hale-api:30875078e139`). Новая сборка поставлена на iPhone 3 ноября.
- Займы: «Погасил» с датой и суммой для любых, «Удалить» только для внесённых вручную. Меньше остатка: займ открыт с новым остатком. Больше: разница идёт в обслуживание. Лимит дня пересчитывается сразу. В «Плане» строка «Займы»: статистика и списки «Открытые», «До начала учёта», «Погашенные».
- Обслуживание: проценты, штрафы, комиссии и выплаты кредиторам сверх тела займа. На настоящих данных ещё не сверялось: посмотреть после деплоя.
- «Что это за перевод?»: сумма, количество, дата последнего и влияние каждого ответа на лимит. Ответ применяется ко всем переводам получателю, меняется из карточки операции. Новый тип операции `loan_out` («Дал в долг»).
- «Близкий человек, регулярно» (решение владельца): переводы считаются в лимите, кроме совпавшего с платежом из плана: он закрывает платёж и лимит не тратит.
- Проверено в симуляторе на локальном сервере с тестовыми данными. Проход по новым экранам на iPhone и сверка настоящих цифр займов за владельцем.

Известные ограничения:
- Банк не показывает возврат старых займов, поэтому «возвращено» считает только связанное с операциями и отмеченное вручную.
- «Погасил» нельзя отменить. Если банковская выплата придёт после ручной отметки, она уйдёт на следующий короткий займ.
- Входящий перевод с «Ждёт ответа» открывает то же окно, но ответы действуют только на исходящие, и вопрос остаётся. Так было и раньше.

## «Оплачено» для платежа из плана
Ветка `feat/pay-from-plan`, ещё не слита и не выкачена: деплой только с согласия владельца. По просьбе владельца: квартплата оплачена наличными, а записать её было некуда.
- Прошедший платёж в «Скоро платить» подсвечен спокойным красным (дата и подпись «просрочен», токен `color.status.danger`).
- Нажатие на платёж открывает окно с одной кнопкой «Оплачено»: платёж закрывается, деньги под него больше не откладываются. Раньше закрыть вручную можно было только налог.

Наличные уменьшаются, лимит не тратится (строка `obligation` на кошельке, связана через `scheduled_payments.transaction_id`). Если по записям наличных меньше суммы, переключатель неактивен с подсказкой: минуса в кошельке не бывает. Решение владельца: в «+» отдельного вида для платежей нет, одно место.

- `TodayDto.upcoming` получил `currency`. Новый маршрут `POST /cash/payments/:id`, миграций нет.
- Проверено в симуляторе на локальном сервере: подсветка, оплата из кошелька, неактивный переключатель при нехватке. «Оплачено» без наличных и удаление строки покрыты автотестами.

## Подводные камни сборки
- `pod install` запускать только с `LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8`, иначе падает.
- `pod install` поверх существующих `ios/Pods` стирает метки версий React, Hermes и зависимостей, а файлы оставляет от последней сборки. Сборка падает на линковке или при запуске. Лечение: удалить `ios/Pods`, поставить заново.
- `expo run:ios` в конце открывает приложение на порту 8081. Если там работает другой Metro, приложение смотрит на настоящий сервер: для локальной проверки сразу закрыть его и открыть свой порт.
- Касания в симуляторе иногда доходят с задержкой: после нажатия ждать 2 с и только потом снимать экран, иначе следующее нажатие откроет не то окно. Плавающая кнопка меню разработчика стоит поверх «Закрыть» в окнах.
- Инструмент симулятора набирает текст в текущей раскладке, а она русская: латиница уходит кириллицей (`voxiuqfaiw` становится `мщчшгйафшц`). Для тестового пароля брать только цифры. Короткие нажатия он теряет, нужна длительность от 0,2 с. Его `touch_path` и `swipe` не годятся для проверки жестов в окнах: настоящий жест даёт `app_drag` через управление окном Simulator.
