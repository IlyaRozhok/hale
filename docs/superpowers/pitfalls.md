# Pitfalls: build, tests, simulator, agent environment

For agents, in English. Each item cost someone time once. When you hit a new one, put it in your report; the lead adds it here.

## Agent environment

- **Node 22 in an isolated working copy.** The environment rejects `source ~/.nvm/nvm.sh && nvm use 22`. Put the path in front of the command instead: `PATH="$HOME/.nvm/versions/node/$(ls $HOME/.nvm/versions/node | grep '^v22' | sort -V | tail -1)/bin:$PATH" pnpm …`. In a chain like `cd apps/mobile && npx jest` the path goes after the `&&`, in front of `npx`.
- **Git in an isolated working copy** is accepted only as a separate simple command: no `cd`, `&&` or `PATH` override on the same line.
- **`gh pr checkout N` fails** while the PR's branch is held by the builder's working copy. A reviewer uses `gh pr view N --json headRefOid`, `git fetch origin pull/N/head`, `git checkout --detach <sha>`.
- **`gh pr merge --delete-branch`**, for the same reason, merges the PR but stops at deleting the local branch and does not delete the branch on GitHub. After the merge: `git push origin --delete <branch>`.
- **Compound commands in an isolated working copy.** A Bash command that mixes a long heredoc (for example `python3 - <<EOF` editing files) with `cd … && PATH=… npx jest`, or with `git`, is refused as "too complex to verify that it stays inside the worktree". Split it: put the script in a file in the scratch directory and run it as its own command. On 12 November 2026 two builders also reported a refusal with the same message for a heredoc with no `git` or `npx` on the line; a reviewer the same day could not reproduce it (a plain `cat > file <<'EOF'` into the scratch directory was accepted), so the exact condition is not known. Later the same day another reviewer had `cat > file <<'EOF'` with TypeScript content refused three times, into the worktree and into the scratch directory alike, while `printf '%s\n' '…' > file` was accepted. If it is refused, create the file with the Write tool, or with `printf` when the agent has no Write tool. A builder later that day had `python3 - <<'EOF'` followed by `PATH=… npx jest` in one command accepted, and `git -C .` refused: treat the refusal as intermittent, not as a fixed rule.
- **The simulator tool does not work in a scheduled run.** `mcp__Claude_Code_iOS_Simulator__control` answers "Mobile simulator tools require an attended session" when the session was started by the schedule. The stand and Metro still start, but nothing can be tapped. The owner writing in that session later does not change it: the tool still refuses, so screens can only be checked in a session the owner started. Do not drive the Simulator window another way: skip the screen check, stop the stand, and say in the summary which screens nobody saw (12 November 2026).
- **A builder subagent without `isolation: "worktree"` works in the lead's own working copy** (13 November 2026: the А21 builder checked out its branch in the lead's worktree). Harmless when the lead's copy is clean, but the lead then has to switch back to `origin/main` after the merge. Start builders with worktree isolation.
- **The full type check** (`pnpm typecheck`) takes about 6 GB of memory. No more than two builders at once; reviewers do not run it.
- **`/usr/bin/python3` (3.9) rejects a script file with long Cyrillic lines** with "SyntaxError: Non-UTF-8 code starting with ..." although the file is valid UTF-8 (16 November 2026, editing backlog.md). Run it as `python3 -c "exec(open(PATH, encoding='utf-8').read())"`, or keep the Russian text in a separate file the script reads.
- **zsh and unquoted globs in `grep --include`.** The shell here is zsh: `grep -rn pattern dir --include=*.tsx` fails with "no matches found" before grep runs, and the rest of a compound command is lost with it. Quote the glob (`--include='*.tsx'`) or list the directories instead.

## Tests

- **Tests with sheets.** A sheet closes with a 200 ms animation and only then disappears. In tests the list under the sheet can be pressed while it is closing (on the phone the scrim blocks that), and the same sheet reopened for another row lives out the old animation and closes. So after «Закрыть» first wait until the sheet is gone (`waitFor(... toBeNull())`), and only then press on. Without this a test passes on a fast machine and fails in CI (11 November 2026: two tests, fixed).

- **A loading state that shows the same text as the loaded one.** On «Итоги» the subtitle («Ноябрь, 1–16») is visible while the month still loads; a test that waits for it and then asserts rows is flaky. Wait for text only the loaded data produces (an amount, a row) before asserting (16 November 2026, В2).
- **Reading CI.** `gh pr checks N | tail -2` exits 0 even when a check failed, so a pipe's exit code says nothing. Read every line of `gh pr checks N` and confirm `pass` on both `check` and `image` for the current head. On 15 November 2026 the lead told the owner CI was green on PR #76 when `check` was red; the reviewer caught it.
- **Flaky server tests.** On 13 November 2026 two builders each saw one full `npx vitest run` fail and then pass on a rerun: once 2 files right after `pnpm typecheck` (which files was not captured), once `apps/api/test/notifications.e2e.test.ts › tick › allows one ordinary notification a day, by log`. The first passed on the next two full runs; the second passed alone and on a second full run. CI did not see either. If it happens, rerun once and name the failing test in the report. Later that day a builder running `npx vitest run` and `npx jest` at the same time saw `today.e2e.test.ts › borrowed › ignores loans from before the last received income` fail once; the reviewer could not reproduce it in four runs. Do not run the two suites in parallel.
- **`jest -t` matches the test name, not strings inside the test.** On 13 November 2026 a builder reported that `npx jest -t '<Cyrillic pattern>'` matched nothing; a reviewer could not reproduce a Cyrillic problem (`-t 'Траты'` matched fine). The pattern was most likely an interface string from the test body, not from an `it(` title. Check the `it(` title before choosing the pattern.

- **`Login.test.tsx` on a cold run.** Right after `pnpm install`, the first full `npx jest` can time out (5000 ms) in "signs in with the password and device name"; alone or on a second run it passes. Seen once by a reviewer on 12 November 2026, not in CI.

- **A new table needs three edits.** The migration, the table list in `apps/api/test/migrations.test.ts`, and `DEFAULT_TABLES` in `infra/restore-check.sh` — `infra/test/scripts.test.ts` fails otherwise. Put all three in the builder's «Где» (15 November 2026, Б8, Б21, Б11).
- **`unmount()` returns a promise** in the installed `@testing-library/react-native`. Rendering again in the same test without `await unmount()` overlaps `act()` and breaks later tests in the file (15 November 2026, Б11).
- **`CheckModule` must stay last in `app.module.ts`.** There is an import cycle around `today/` and `plan/`; importing it earlier leaves `LimitService` undefined in `PlanService` and every e2e suite fails (15 November 2026, Б11).
- **The same holds for the `import` line of any new module that imports `TodayModule`** (for the `Clock`). With `import { InsightsModule }` placed alphabetically before `MonoModule`/`PlanModule`, every e2e suite failed with "Nest can't resolve dependencies of the PlanService (DataSource, Clock, ?)". Put both the `import` statement and the module entry next to `CheckModule`'s, after the others (16 November 2026, В1).

## iOS build

- Run `pod install` only with `LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8`, otherwise it fails.
- `pod install` over an existing `ios/Pods` wipes the version stamps of React, Hermes and the dependencies but leaves the files from the last build. The build then fails at linking or at launch. Cure: delete `ios/Pods` and install again.
- A rebuild does not always move the 7-day signature. Xcode may reuse the existing Personal Team provisioning profile while it is valid (seen on 12 November 2026; the build of 11 November got a fresh one), and then the app expires on the old date. Read the real date after a build: `strings <DerivedData>/Build/Products/Release-iphoneos/Hale.app/embedded.mobileprovision | grep -A1 ExpirationDate` (the `security` command is denied to agents).
- `expo run:ios` ends by opening the app on port 8081. If another Metro is running there, the app looks at the real server: for a local check close it at once and open your own port.

## Simulator and stand

- **Stopping Metro.** `pkill -f "expo start"` does not find the stand's Metro (the process is named differently). Use `lsof -ti tcp:8082 -sTCP:LISTEN | xargs kill`.
- **Taps arrive late sometimes.** After a tap wait 2 s and only then take a screenshot, otherwise the next tap opens the wrong sheet and the screenshot shows the screen from before the tap. The floating developer-menu button sits on top of «Закрыть» in sheets.
- **The simulator tool types in the current layout, and it is Russian:** Latin letters arrive as Cyrillic (`voxiuqfaiw` becomes `мщчшгйафшц`). Use digits only for the test password, or paste it (see `scripts/sim/README.md`). The tool loses short taps: use a duration of at least 0.2 s. Its `touch_path` and `swipe` are no good for checking gestures in sheets: a real gesture needs `app_drag` through control of the Simulator window.
- **Pasting the stand password.** Two short taps on the field did not bring up the edit menu on 13 November 2026; a long press (0.8 s) did, and «Paste» was at (55, 492). After the stand is restarted the password is new: copy it again with `xcrun simctl pbcopy`.
- **The bridge plan slider** in its sheet moves with the simulator tool's `touch_path` (start on the thumb, several points, 150 ms apart). Taps right after a pull-to-refresh are often lost: wait for the refresh to end and tap again.
- **Confirming a bridge plan on the stand** needs a credit limit: `seed.sql` gives `sim-black` none, and then no amount can be confirmed (task А22). Give it one without changing own money: `UPDATE accounts SET credit_limit=3000000, balance=6764000 WHERE external_id='sim-black';`. A past transition day for the calendar: `UPDATE daily_snapshots SET mode='bridge_start' WHERE local_date=(now() AT TIME ZONE 'Europe/Kyiv')::date - 3;`.
- **No `UNSAFE_getAllByType` on `screen`.** The installed `@testing-library/react-native` does not have `screen.UNSAFE_getAllByType`. To check the order of elements on the screen, use `screen.getAllByText(/./)` and compare positions (see `apps/mobile/src/components/RecipientLabelSheet.test.tsx`).
- **Settings do not refresh by pull** while the sheet is open: close and reopen it to see a new «Сверка» result. After `down.sh` + `up.sh` the app must sign in again (new password and token); relaunch it with `xcrun simctl terminate booted com.irozhok.hale` and the `openurl` from the README. A stand server with the ledger check on: `LEDGER_CHECK_ENABLED=true scripts/sim/up.sh` (the variable passes through to the API). Only nightly (`scheduled`) runs are shown in the app (15 November 2026).
- **Check `mergeable` before deleting a PR branch.** On 16 November 2026 the lead ran `gh pr merge N --squash --delete-branch …; git push origin --delete <branch>`; the merge failed on a conflict (another PR had just been merged), and the `;` still deleted the branch on GitHub, which closed the PR. It was restored by pushing the approved commit back (`git push origin <sha>:refs/heads/<branch>`) and `gh pr reopen N`. Read `gh pr view N --json mergeable` first and delete the branch only after `state` is `MERGED`.
- **TypeORM `m.query` with `DELETE … RETURNING`** returns `[rows, count]` in this repo, so `(…)[0]` is the rows array, not the first row (found by the Б22 builder, 16 November 2026).
